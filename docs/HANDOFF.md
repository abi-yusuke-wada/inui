## 検証結果

- 今回の変更: TOML構文とCodexによる設定読み込みを確認し、`network_proxy = true` が有効。既存のファイルdeny・承認設定・作業領域の継承が変わっていないことと、許可先がGitHubの2ホストだけであることを確認した。実通信と許可外ホストの拒否は未検証。
- Nix環境で `make sandbox-check` が成功。Codex CLI 0.165.0が既定のプロジェクト設定を読み込めることを確認した。
- ダミー9ケース（プロジェクト内・入れ子・プロジェクト外の `.env` 類、シンボリックリンク、プロジェクトとホームの `.aws`）について、Pythonの読み取り・`cat`・書き込みの拒否を確認。通常ファイルの編集と作業領域外の書き込み拒否も確認し、ダミーは削除済み。
- シンボリックリンクで拒否を確認したのは、作業領域内の `.env` を指すファイルへのリンクと、作業領域内のディレクトリへのリンク経由の読み取り。作業領域外のディレクトリへのリンク経由では `.env` を読み取れるため（ADR-0002）、拒否ではなく `make sandbox-check` による事前検出で対策する。
- 起動時に存在しない `~/.aws` は拒否されないため、作業領域の `.aws` とあわせて `flake.nix` の `shellHook` で事前に作成し、作成後に置いたダミーファイルの読み取りが拒否されることを確認した。
- macOS・Windows、外部MCPツール等の別経路は未検証。実際の認証情報は使っていない。
