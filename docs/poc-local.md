# ローカルPoCの実行と確認

休暇申請・交通費精算・申請状況の確認・予定比較を、開発機で実NLIと接続して確認する手順。設計判断と部署展開との区別は[ADR-0008](adr/0008-local-poc-workflows.md)、対象と完了条件は[MVP](../MVP.md)を参照する。

## 準備と起動

リポジトリのルートでdevShellへ入り、公開npm依存を取得する。direnvでdevShellが有効なら`nix develop`は不要。`app-setup`はネットワークを使い、依存のインストールスクリプトは実行しない。

```sh
nix develop
make app-setup
```

local-jevが未導入の場合だけ、次を実行する。Python依存の取得にネットワークを使う。

```sh
make jev-local-setup
```

固定revisionの重み・tokenizerが未準備なら、次を実行する。`jev-local-pin-model`は必要なファイルを取得し、ローカルのモデルカードを固定snapshotへ向ける。取得・保存にはネットワークとディスク容量が必要。[固定revisionの説明](jev-connection-check.md#実測revisionの重みとtokenizerの再取得)も参照する。

```sh
make jev-local-pin-model
```

アプリと推論サーバーをまとめて起動する。

```sh
make app-dev
```

不足するサービスだけを起動し、推論サーバーの準備完了まで待ってからアプリを使える状態にする。モデル・重みは取得済みのものだけを使い、起動時に外部へダウンロードしない。起動済みの正常なサービスは再利用する。

このターミナルを開いたまま、ブラウザで次を開く。終了はCtrl+Cで、このコマンドが起動したプロセスだけを停止する。再利用した既存プロセスは停止しない。

- 自然言語UI: [http://127.0.0.1:3000/](http://127.0.0.1:3000/)
- 比較用の旧形式: [http://127.0.0.1:3000/legacy](http://127.0.0.1:3000/legacy)

どちらも同じ業務API・フォーム・予定画面・データを使う。自然言語UIは入力欄から画面を選び、旧形式はメニューから同じ画面を開く。アプリは固定のローカルNLIを呼び、公式APIキーの設定有無では切り替えない。従来の`make jev-probe`は別の検証用プローブであり、アプリの呼び出し経路には使わない。

## 申請と保存の確認

初回の申請データは2件で、休暇1件が承認済み、交通費1件が申請中。差し戻しは0件。`有給を取りたい`、`交通費を精算したい`、`申請の状況を見たい`で対応する画面を確認する。文章に含まれる日付・金額・状態は自動補完しない。

保存は入力例の確認後に行う。

1. 休暇申請で取得日`2026-11-03`、区分「全日」を入力し、内容を確認して確定する。
2. 交通費精算で利用日`2026-11-01`、金額`1,200`円を入力し、内容を確認して確定する。
3. 申請一覧が4件になり、追加2件が申請中であることを確認する。状態の絞り込みは画面で選ぶ。
4. 一覧の再表示後、さらにCtrl+Cで停止して`make app-dev`で起動し直した後も、追加2件が残ることを確認する。

自然言語の送信やフォームの表示だけでは保存しない。保存後の応答が不明な場合は、一覧で結果を確認してから次の操作を判断する。

## 予定比較の確認

`山田太郎さんと佐藤花子さんの予定を見たい`と入力する。社員辞書の全名に一致した2人が選択済みとなり、初期日の`2026-11-02`の予定を表示する。

サンプル社員は山田太郎・佐藤花子・鈴木一郎・山田花子。一意な姓は選択できるが、`山田さん`は同姓の候補を画面で確認して選ぶ。`田中さん`のような未知名は自動で別の社員へ置き換えず、案内に従って選び直す。名前なし・選択不足の場合も全員へ広げず、比較する2名以上を指定する。

文章に「明日」等があっても予定日は初期値のまま。画面の予定日を`2026-11-03`へ変更して「予定を表示」を押すと、別日のサンプルを確認できる。他の日は予定なしを表示する。予定の登録・削除は行わない。旧形式では「確認する」から「予定比較」を開き、社員と日付を明示的に選ぶ。

## 失敗・リセット・テスト

対象外機能・未対応操作・曖昧入力では、保存せず固定の案内を表示する。推論の接続失敗、不正な応答、本文受信を含む25秒の期限超過は安全なエラーを表示し、入力の修正・再試行ができる。上流の例外本文は表示しない。推論接続先はloopbackだけを許し、アプリのHostとPOSTのOriginも制限する。

初期状態へ戻すときはアプリをCtrl+Cで停止してから、次を実行する。

```sh
make app-reset
make app-dev
```

`app-reset`は`.local-poc/app.sqlite`の申請を初期2件へ戻す。追加した申請は消える。予定・社員のサンプルや、`.local-jev`のモデル重みは変更しない。

型検査・ビルド・コア/API/SQLite/UI操作のテストは`make app-check`、コアの通信契約・失敗処理だけは`make core-check`で確認する。固定応答を注入したテストは実NLI精度の証拠にはしない。

`make app-model-check`はキャッシュ済みモデルを直接呼び、既存13入力と予定比較・未対応操作の6入力を検証する。外部通信やHTTPを使わないため、HTTP経路とは別の記録になる。サーバー2つが起動したら、別のdevShellで`make app-probe`を実行すると、19入力を実際の受付APIへ送って分類と人名選択を照合できる。申請データは保存しない。

起動からHTTP検証までを1コマンドで行う場合は、次を使う。検証が終わると、このコマンドが起動したサーバーを停止する。画面を使い続ける場合は`make app-dev`を使う。

```sh
nix develop --command make app-smoke
```

`app-smoke`も既存の正常なサービスは再利用する。別サービス・別モデル・接続権限エラーは上書きせず停止する。手動で分けて管理したい場合だけ、`make jev-local-serve`と`make app-run`を別ターミナルで使う。

固定revisionの実Engine検証では19/19件と人名選択4/4件が一致した。[保存応答](poc-nli-responses-2026-11-10.jsonl)は`make app-replay-check`で推論・通信なしに再検証できる。これは新たなHTTP実測や実ブラウザの確認とは区別する。直近のEngine検証結果は`.local-poc/model-verification.json`、HTTPプローブ結果は`.local-poc/http-verification.json`へ保存する。

利用者ホストの[HTTP検証結果](poc-http-results-2026-11-11.json)でも、19/19件と人名選択4/4件の一致を確認した。これはCLIからIntent受付APIへ送った結果であり、ブラウザ・保存・正式な30秒条件の結果とは区別する。

`app-probe`の失敗時は、端末に入力ごとのHTTPステータスやエラー種別を表示する。`make app-diagnose`でアプリとlocal-jevを個別に確認でき、詳細は`.local-poc/connection-check.json`へ保存する。local-jev側の診断には固定入力1件を送る。アプリに接続できても推論サーバーが停止していれば、Intentの受付は503を返す。

## ローカルで確認できる範囲

これは単一の検証利用者向けのローカルPoCで、Turso・OAuth・AWSへの配置は未実装。SQLiteの再起動後の保持を、Tursoや新しいLambda実行環境での永続化確認として扱わない。公開クラウド資源は作らず、部署向けにそのまま公開しない。

モデルの部署向け配置、Lambdaでの起動・RSS・費用、ブラウザからの正式30秒測定（Issue #15）、音声入力と旧形式との評価は残る。ローカルで画面を開けたことや、コアの25秒期限だけでこれらを完了したとは扱わない。
