# ADR-0011: 作業の再開画面のために、登録したリポジトリのgitを読み取り専用で読む

- 状態: 決定（2026-11-18、利用者の回答による）。今回は業務API（`GET /api/resume`）までとし、画面とIntentは、並行して作っているモックアップが決まってから追加する。
- 関連: [Issue #33](https://github.com/abi-yusuke-wada/inui/issues/33)、[Issue #31](https://github.com/abi-yusuke-wada/inui/issues/31)、[ADR-0009](0009-feature-packages-and-subject-change.md)、[実行手順](../poc-local.md)

## 背景

- 利用者（システムエンジニア）は「今から何をすればいいか」を探すところから作業を始める。「inuiの続きをやりたい」などの入力で、リポジトリの作業状況（ブランチ、未コミットの変更、最近のコミット、自分のPRとそのレビュー・CI、引き継ぎメモ）をまとめて表示する画面を作る（#33）。
- 利用者は、並行作業を `.worktrees/` の下のworktreeで行う。同じリポジトリの複数のworktreeを、まとめて見る必要がある。
- これまでの業務APIは、自分のDBとGitHubのAPIしか読んでいなかった。手元のリポジトリを読むには、アプリのサーバーから `git` を動かす必要があり、どのリポジトリを、どこまで読むかを決める必要がある。

## 比較した案と費用

### 手元のリポジトリの読み方

| 案 | 費用・作業負担 | 判断 |
| --- | --- | --- |
| `git` のコマンドを、決まった引数で読み取り専用に実行する | 依存は増えない。gitの設定で外部のプログラムが動く仕組み（fsmonitor、署名の検証等）を、こちらで止める必要がある | 採用 |
| JavaScriptで実装されたgit（isomorphic-git等）を使う | 外部のプログラムは動かないが、依存が増え、worktreeや状態の判定がgitと一致しない場合がある | 不採用 |
| `.git` の中のファイルを直接読む | 依存は増えないが、インデックスやパック形式の読み取りを自前で保守することになる | 不採用 |

### 読むリポジトリの登録（利用者の選択）

| 案 | 費用・作業負担 | 判断 |
| --- | --- | --- |
| 環境変数 `INUI_REPOSITORIES` に絶対パスを並べる | 画面もDBも要らない。読める場所を、利用者が明示したものだけに限れる | 採用 |
| 画面から登録してDBへ保存する | 使いやすいが、パスの検証と登録画面が必要になる | 不採用 |

### 画面に出すリポジトリ（利用者の選択）

| 案 | 判断 |
| --- | --- |
| 登録したものを全部、最近作業した順に出す | 採用。入力から値を取り出さないため、MVPで延期した自然言語からの自動補完に触れない |
| 入力に含まれる登録名（inui等）を照合して、1つだけ開く | 不採用。PR #26でなくした、画面へ引数を渡す経路を戻すことになる |

### 自分のPRのレビューとCIの状態（利用者の選択）

最初の版から入れる。タスク画面と同じトークン（`INUI_GITHUB_TOKEN`）で、GitHubのGraphQL APIを読む。登録したリポジトリごとの検索を、別名を付けて1回の要求にまとめる。

## 決定

- 業務機能のパッケージ `packages/features/resume` に、`GET /api/resume` を置く。リポジトリにもGitHubにも書き込まない。
- 読むリポジトリは、環境変数 `INUI_REPOSITORIES`（絶対パスのカンマ区切り、10件まで）に並べたものだけとする。1つでも形式が誤っていれば、どれも読まずに `invalid_config` を返す。未設定なら、未登録であることだけを返す。`make app-dev` の起動スクリプトは、この変数をアプリにだけ渡す。
- `git` は次の条件で動かす。
  - シェルを使わず、引数を配列で渡す。使うのは `rev-parse`、`worktree list`、`status`、`log`、`config --get remote.origin.url` だけとする。
  - 環境変数はPATHだけを引き継ぎ、呼び出し元の `GIT_DIR`・`GIT_CONFIG_*`・`HOME` 等は渡さない。このため、利用者全体の設定（`~/.gitconfig`）は読まない。
  - 表示のためだけに外部のプログラムが動く設定を止める（`core.fsmonitor=false`、`log.showSignature=false`）。`GIT_OPTIONAL_LOCKS=0` で、`status` がインデックスを書き換えないようにする。サブモジュールの状態は読まない。
  - 通信しない（環境変数 `GIT_ALLOW_PROTOCOL` を空にして、すべてのプロトコルを禁止する）。部分クローン（partial clone）では、足りないオブジェクトをgitが自動で取りに行き、リポジトリへ保存するため。git 2.34 には、これだけを止める `GIT_NO_LAZY_FETCH`（2.44から）がない。`protocol.allow=never` はリポジトリの設定の `protocol.<名前>.allow` に負けるため、設定より優先されるこの変数を使う。足りないオブジェクトが要る読み取りは失敗として扱う。
  - 1回の実行は5秒・出力1MBまでとし、同時に動かすのは8つまでにする。
  - 失敗の理由は、固定のコード（`not_found`、`not_repository`、`unsafe_repository`、`timeout`、`git_failed`）だけを返し、パスや標準エラーの本文は返さない。
- 1つのリポジトリで表示するのは、worktree 8つ、worktreeごとに変更のあるファイル30件と最近のコミット5件までとし、超えた分は数だけを返す。1回の要求で動かすgitの数を抑えるため、worktreeは読むのもこの8つまでとする。
- 引き継ぎメモは、読んだworktree（上の8つ）の `docs/HANDOFF.md` のうち最も新しく更新されたものを読む。9つ目以降のworktreeのメモは選ばない。未コミットの変更があればファイルの更新日時、なければ最後にコミットした日時で比べる。履歴を読めなかったメモ（時間切れ、部分クローンで古い履歴がない等）は、未コミットか古いものかを決められないため選ばない。64KBまでを読み、シンボリックリンクや、リンクでworktreeの外を指す場所にあるものは読まない。開いたファイルは、確かめたものとiノードが同じかを比べ、Linuxでは開いたファイルそのものの場所（`/proc/self/fd`）がworktreeの中かも確かめる。
- originのURLが github.com のリポジトリなら、自分が作った未完了のPR（20件まで。超えた分は件数だけを返す）について、レビューの状態と最新のコミットのチェック（CI）の結果を読む。URLに認証情報が含まれていても使わない。GitHubを読めなくても、手元のgitの状況は返す。
- GitHubを読む処理は、タスク画面（`packages/features/tasks`）と同じ方針（リダイレクトに従わない、期限を設ける、応答を検証して固定のコードへ置き換える）で、このパッケージの中に持つ。機能ごとに切り離せるよう、タスク画面の処理は参照しない。

## 影響と未決事項

- アプリのサーバーが、利用者の登録したリポジトリで `git` を動かすようになった。リポジトリの設定（`.git/config`）は利用者自身のものとして信頼する。ただし、`status` が内容を確かめるときに使うフィルター（Git LFS等）は、利用者が普段gitを使うときと同じく動く。
- ブラウザから読めるのは、登録したリポジトリの状況と引き継ぎメモの本文だけで、任意のパスは指定できない。サーバーは従来どおり127.0.0.1でだけ待ち受ける。
- 引き継ぎメモの場所の検査は、Linux以外のOS（macOS等）ではiノードの比較までになる。Node.jsには `openat` がなく、開いたファイルから場所を得る方法もないため、確かめる処理と開く処理の間で途中のディレクトリ（`docs`）をリンクへ差し替え続けると、外にある同じiノードのファイルを読む余地が残る。worktreeを同時に書き換えられるプロセスが要り、開発機（WSL）では起きないため受け入れる。
- 部署向けにサーバーへ置く場合、この画面はそのままでは動かない（手元のリポジトリを読むため）。展開の形は、ローカルでの検証の後に決める（#31）。
- トークンにCIの結果を読む権限がない場合に、GitHubがnullとエラーを返すか、nullだけを返すかは、実際のトークンで確認していない。エラーが返った場合は「不明」、nullだけの場合は「チェックなし」と表示する。エラーの場所（`path`）がPRの中を指していれば、そのPRだけを「不明」にする。最新のコミット（`commits`）は省略できない欄のため、読めないとエラーでPRごとnullになる。その場合は、CIの状態を読まずに要求をもう1回だけ送り、PRの一覧を残してCIの状態をすべて「不明」にする。fine-grained tokenで `commits` を読むのにContentsの読み取り権限が要るかも、実際のトークンで確認していない。
- 画面、Intentの追加と分類の検証（#32）、旧形式のメニューへの追加は、モックアップが決まってから行う。
- GitHubの読み取りの処理がタスク画面と重複している。共通部品（`kit`）へ移すかは、PR #26のマージ後に検討する。
